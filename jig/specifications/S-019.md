# Outcome File Validation

Validate outcome files (`jig/outcomes/O-*.md`) against A001 contract requirements.

**Acceptance Criteria**:
- Parse YAML frontmatter from outcome markdown files
- Required fields validated: `id`, `type`
- ID format validated: must match `O-{number}` pattern
- ID uniqueness validated: no duplicate outcome IDs across all files
- Excluded fields rejected: `brick` must NOT be present
- Error messages include file path and specific field violations
- Validation works when no outcome files present (outcomes are optional)

**Rationale**: Ensures outcome files conform to A001 contract. Outcomes are optional artifacts, so validator must gracefully handle their absence.

**References**: A001 §10 (Validation Rules), AG026 (Linter Proposal)
