# Layout Algorithms Support Compound Nodes

All layout algorithms MUST correctly position brick containers and member nodes.

**Acceptance Criteria**:
- Hierarchical (Rows) layout arranges bricks top-to-bottom with members inside containers
- Hierarchical (Columns) layout arranges bricks left-to-right with members inside containers
- Force-directed layout clusters brick members together within boundaries
- Circular layout positions bricks in circle with members visible inside
- Grid layout organizes bricks in grid with members positioned inside
- Brick container boundaries visually clear in all layouts (no overlapping edges obscuring borders)
- Brick labels don't overlap member nodes in any layout
- Member nodes stay within brick boundaries (adequate padding configured)
- Zoom-to-fit includes all brick boundaries (not just member nodes)
- Layout changes complete within reasonable time (<2 seconds for ~125 nodes, 5 bricks)
- Compound node parameters tuned for clarity (nestingFactor, gravity, padding)
- Manual testing confirms all layouts work with collapsed bricks
- Manual testing confirms all layouts work with filtered bricks

**Rationale**: Layout integration ensures brick visualization works across all visualization modes. Proper compound node support is essential for usable brick boundaries.
