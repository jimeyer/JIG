# Brick Definition Validation

Validate brick definitions in `jig/bricks.yaml` against A001 contract and implementation graph.

**Acceptance Criteria**:
- Parse `jig/bricks.yaml` structure (list of brick objects)
- Required fields validated: `id`, `name`, `units` (must be present on each brick)
- ID format validated: must match `B-{number}` pattern
- ID uniqueness validated: no duplicate brick IDs across all bricks
- Unit prefix validated: all units must start with `M-`, `C-`, or `F-`
- Unit references validated: all units must exist in `implementation-graph.ndjson`
- Excluded fields rejected: `depends_on`, `public_api`, `specs` must NOT be present
- Error messages include brick ID and specific violations
- Requires implementation graph: error if `implementation-graph.ndjson` not found

**Rationale**: Ensures brick definitions are well-formed and reference valid implementation graph nodes. Prevents partition validation errors.

**References**: A001 §10 (Validation Rules), AG026 (Linter Proposal)
