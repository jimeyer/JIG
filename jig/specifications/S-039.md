# Circular Dependency Detection

Brick dependency graph SHALL be acyclic (DAG) at all layers including layer 0.

**Acceptance Criteria**:
- Validation builds directed graph of brick dependencies
- Cycle detection algorithm runs on full dependency graph
- All cycles are detected and reported (not just the first one)
- For each cycle, the cycle path is shown (B-a → B-b → B-c → B-a)
- Error message clearly indicates this is a circular dependency
- Cycles at layer 0 are detected and reported (layer 0 bricks may depend on each other, but no cycles)

**Rationale**: Circular dependencies indicate architectural problems and break the layer hierarchy. Even at layer 0 (where bricks may depend on each other), cycles create brittle coupling and prevent clear understanding of system structure. All brick dependencies must form a directed acyclic graph (DAG).

**Valid (No Cycles)**:
```
B-a → B-b → B-c
B-d → B-b
(All paths flow one direction, no loops back)
```

**Invalid (Has Cycle)**:
```
B-a → B-b → B-c → B-a
(Returns to starting point, creates cycle)
```

**Cycle Detection Algorithm**:
- Use depth-first search (DFS) with visited and recursion stack
- When node is in recursion stack and visited again, cycle detected
- Extract cycle path by backtracking through recursion stack
- Report all unique cycles found

**Example Error**:
```
ERROR: Circular dependency detected

Cycle: B-auth → B-users → B-session → B-auth
  Functions involved:
    F-auth.login → F-users.get_user
    F-users.validate_permissions → F-session.check_session
    F-session.create → F-auth.authenticate

This circular dependency violates A001 Section 10 (rule #13).

Fix: Refactor to break the cycle by extracting shared functionality
to a lower-layer brick or removing one of the dependencies.
```
