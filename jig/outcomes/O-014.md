# Layer Structure Visibility

**Value:** Developers can visualize the current layer structure and automatically discover appropriate layer assignments from dependency analysis.

**Acceptance:** `jigy layers` displays brick groupings by layer with dependencies and function counts in readable terminal format. `jigy layers suggest` analyzes dependencies and recommends layer assignments using topological sort, with `--apply` flag to update bricks.yaml.

## Rationale

Layer structure is invisible in raw source code. Without visualization, developers cannot see the architectural organization at a glance. Without automated layer assignment, discovering appropriate layers requires manual dependency analysis.

AG029 Section 6-7 specifies CLI commands for layer management to address these needs:

1. **Visualization gap**: Developers need to see which bricks are at which layers, what dependencies exist, and whether the architecture is a valid DAG. `jigy layers` makes architecture explicit by grouping bricks by layer and showing dependency relationships.

2. **Assignment discovery**: When starting with flat architecture (all layer 0) or refactoring existing code, manually analyzing dependencies to assign layers is tedious and error-prone. `jigy layers suggest` mechanically derives appropriate layers using the algorithm: `layer = max(dependency_layers) + 1`.

These commands enable team discussions about system organization, provide a mechanical starting point for layer assignments, and make architectural intent visible throughout development. Visualization works on both flat architectures and multi-layer systems, supporting projects at any stage of architectural maturity.

## Success Criteria

The CLI commands must:
1. **Visualization** (`jigy layers`):
   - Load bricks.yaml and implementation-graph.ndjson
   - Group bricks by layer (Layer 0, Layer 1, Layer 2, ...)
   - Show brick ID, name, function count, and dependencies for each brick
   - Display total summary: brick count, layer count, function count, DAG status
   - Format output for terminal readability using boxes and alignment
   - Support `--summary` (counts only) and `--verbose` (full details) options
   - Indicate cycles if dependency graph is not a DAG (⚠ Cycles detected)

2. **Suggestion** (`jigy layers suggest`):
   - Derive brick dependencies from implementation graph function calls
   - Perform topological sort of brick dependency graph
   - Assign layers using algorithm: bricks with no dependencies → layer 0, others → max(dep_layers) + 1
   - Compare current layer assignments with suggested assignments
   - Display comparison showing current vs suggested with match indicators (✓ MATCHES, ⚠ MISMATCH)
   - Show reason for each suggestion (e.g., "depends on B-x at layer 1")
   - Support `--apply` flag to update bricks.yaml after confirmation prompt
   - Return clear error if circular dependencies exist (cannot assign layers to graphs with cycles)

3. **Integration**:
   - Handle both flat architecture (all layer 0) and multi-layer systems
   - Preserve bricks.yaml format (both wrapper and bare list formats) when applying suggestions
   - Provide clear error messages when layer fields missing or implementation graph unavailable

## Specified By

This outcome is delivered through:
- **S-040**: CLI command `jigy layers` for visualizing brick layer structure with dependencies and summary statistics
- **S-041**: CLI command `jigy layers suggest` for analyzing dependencies and suggesting layer assignments with optional `--apply`
