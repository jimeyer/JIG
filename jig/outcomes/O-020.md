# Configurable Project Structure

**Value:** JIG adapts to diverse project layouts without forcing projects to reorganize their code structure.

**Acceptance:** Projects with non-standard directories (`tests/` vs `test/`, `lib/` vs `src/`) can use JIG by specifying paths in configuration.

## AI Agent Benefit

Agents can work on any project regardless of directory structure by reading JIG's configuration. Without configurable paths, agents would need project-specific heuristics to find source and test files, leading to brittle automation that fails on non-standard layouts.

## Rationale

Existing projects have existing structures. Forcing projects to reorganize directories to adopt JIG creates adoption friction that kills adoption. "Just move your tests from `tests/` to `test/`" sounds simple but requires updating CI, IDE configs, imports, and developer muscle memory.

The right approach is convention over configuration with configuration escape hatches. Standard layouts (`src/`, `test/`, `jig/`) work with zero configuration. Non-standard layouts declare their paths explicitly. Both paths lead to working JIG integration.

Configuration must be version-controlled and explicit. A `jig.yaml` file in the project root declares paths, making the configuration visible and auditable. No hidden defaults that differ from project to project - if paths are custom, they're documented.

This flexibility enables JIG adoption in legacy codebases, polyglot projects with language-specific conventions, and organizations with established standards. JIG meets projects where they are rather than demanding projects meet JIG.

## Success Criteria

The configuration system must:
1. Discover configuration files by searching from current directory upward
2. Support custom source directory paths (replacing default `src/`)
3. Support custom test directory paths (replacing default `test/`)
4. Support custom JIG artifact paths (replacing default `jig/`)
5. Validate configuration schema and report errors with line numbers
6. Work with zero configuration for standard project layouts
